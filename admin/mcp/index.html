How the login works

  1. The client calls /mcp and gets 401 with a WWW-Authenticate header.
  2. It follows that header's resource_metadata URL to find the authorization server.
  3. Cloudflare Access handles registration, the authorization code exchange and token issuance.
  4. The client retries with a bearer token; the Worker verifies its signature and audience.

No API key is stored in the client config. The token is issued by Access and can be revoked from the Zero Trust dashboard.

Tool catalog

Tools are filtered by role before tools/list returns, so a client never sees a call it is not allowed to make. Two rules shape this list: creating and updating a post can never change its status, and hard deletion is not exposed over MCP at all.
